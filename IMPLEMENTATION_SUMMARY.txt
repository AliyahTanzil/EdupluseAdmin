   - Manages curriculum and assessment
   - Verifies marks and coordinates subject teachers
   - Dashboard: /teacher-dashboard (with subject-specific features)

4. DEPARTMENT HEAD
   - Email: depthead@school.com | Password: password
   - Manages entire department
   - Oversees budget, staff, and curriculum
   - Has strategic planning responsibilities
   - Dashboard: /teacher-dashboard (with department-specific features)

================================================================================
SYSTEM ARCHITECTURE OVERVIEW
================================================================================

1. AUTHENTICATION LAYER
   - User logs in with email/password
   - Backend validates and creates JWT token
   - Token includes: user id, email, role, teacherType
   - Frontend stores token and user data in localStorage

2. AUTHORIZATION LAYER
   - ProtectedRoute component checks role/teacherType
   - Sidebar displays role-specific menu items only
   - Backend middleware validates permissions on every API call
   - Data filtered based on role before returning to frontend

3. DATA ACCESS LAYER
   - Regular Teachers: See only their class + subjects
   - Class Teachers: See complete class data
   - Subject Heads: See subject-wide data
   - Department Heads: See department-wide data
   - Admin: See all data

4. ROLE HIERARCHY
   Level 5: Admin (Full Access)
   Level 4: Department Head (Department-wide)
   Level 3: Subject Head (Subject-wide)
   Level 2: Class Teacher (Class-wide)
   Level 1: Regular Teacher (Limited)
   Level 0: Student/Parent (Own data only)

DATABASE USER STRUCTURE
================================================================================

Each user has these fields:

{
  id: string,
  email: string,
  password: string (hashed in production),
  name: string,
  role: 'admin' | 'teacher' | 'student' | 'parent',
  teacherType: 'regular' | 'class_teacher' | 'subject_head' | 'departmental_head',
  
  // For all roles:
  phone: string,
  department: string,
  subjects: string[],
  
  // For regular/class teachers:
  class: string,
  
  // For class teachers:
  classHead: boolean,
  students: string[],
  
  // For subject heads:
  headingSubject: string,
  subjectDepartment: string,
  classes: string[],
  
  // For department heads:
  headOfDepartment: boolean,
  subjectTeachers: string[],
  responsibilities: string[]
}

================================================================================
USING THE PERMISSION SYSTEM
================================================================================

IN FRONTEND COMPONENTS:

// Check user role
import { usePermission } from '../components/ProtectedRoute';

const { hasRole, hasTeacherType, canAccess } = usePermission();

if (hasRole('teacher')) {
  // Show teacher features
}

if (hasTeacherType('class_teacher')) {
  // Show class teacher features
}

// Protect entire route
<ProtectedRoute requiredRoles={['teacher']} requiredTeacherTypes={['class_teacher']}>
  <ClassTeacherPage />
</ProtectedRoute>

// Conditional UI elements
{hasFeature('canMarkAttendance') && <MarkAttendanceButton />}

IN BACKEND:

// Apply RBAC middleware to routes
router.get('/students', authenticateToken, requirePermission('view_students'), handler);
router.post('/attendance/mark', authenticateToken, requireTeacherType(['regular', 'class_teacher']), handler);

// Filter data by role
const filteredData = filterDataByRole(user, data, 'students');
